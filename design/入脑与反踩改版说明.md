# 入脑与反踩 · 改版说明

> 状态：代码已实现并编译通过，待实机验证 ｜ 2026-11-24
> 相关代码：`mods/Viridis/Hype/`、`mods/Viridis/Cards/`

## 1. 为什么改

改版前角色身上同时挂着 **4 个概念**：同接、考子、反踩、串子。实际运行下来有三个问题：

1. **同接只进不出**。每打一张牌 +1、回合结束清零，但全卡池几乎没有人消费它，玩家看不到它有什么用。
2. **考子和反踩意义不明**。考子 = 回合开始涨同接，反踩 = 前 X 张牌不给同接，两者都在描述“同接怎么变”，而当时同接本身又不产生收益，绕了一圈回到原点。
3. **栽培缺燃料**。栽培要把手牌埋进地里 1~3 回合，前期手牌见底，节奏断档。

## 2. 新结构：一个计数器 + 一根双极轴

```
        ┌──────────── 同接（每打一张牌 +1，回合结束清零）
        │                    │
        │ 打牌                │ 卡牌转化
        ▼                    ▼
   入脑（+）←── 互为反面 ──→ 反踩（−）
        │                    │
        ▼                    ▼
  X 拉伸 + 3 同接          X 活力 + 挨打涨同接
```

- **同接** 不再是目标，而是**两端之间的交换介质**：只有卡牌能把它换成入脑或反踩（例如「登山」把所有同接转成反踩）。
- **入脑 / 反踩** 不是 debuff，而是**两个收益引擎**，各自在回合开始产出资源并衰减 1 层。
- 两者**互为反面**：获得反踩时先扣等量入脑，反之亦然；两边都归零就是**黑听**。

## 3. 规则

| 名称 | 规则 |
|---|---|
| **同接** | 每打出一张牌 +1；你的回合结束时清零 |
| **入脑** | 回合开始：获得 X 点**拉伸**、3 点同接，并失去 1 层（X = 层数）。**上限 8 层，溢出的入脑转化为拉伸** |
| **反踩** | 每受到一次伤害（**被格挡的部分也算**）+1 同接；回合开始：获得 X 点**活力**，并失去 1 层。**上限 8 层，溢出的反踩转化为活力** |
| **黑听** | 入脑与反踩均为 0；常态无效果，仅部分卡牌在此状态下追加效果 |
| **栽入** | 本牌被栽培时的额外效果（新关键词，悬停可查） |

> 「受到一次伤害」按 `AfterDamageReceived` 结算：一次攻击若打出多段，每段各算一次；完全被格挡的攻击也算一次（`DamageResult.BlockedDamage` 统计了格挡量）。

## 3.1 HP 条上方的双极滑条

角色血条正上方有一条横条，左半红褐（反踩）、右半松绿（入脑），中间是 0 点（黑听）：

- 指针位置 = 有符号极性 `入脑层数 − 反踩层数`，范围 −8…+8；
- 填充色随方向变化，中间文字显示「入脑 +N / 反踩 −N / 黑听 0」；
- 悬停显示对应关键词说明；
- 只在「小松绿」或身上有入脑/反踩层数时显示。

实现是自绘控件（不依赖游戏内部场景），代码在 `Hype/PolarityBarUI.cs`，通过 Harmony 挂在 `NCreatureStateDisplay` 上、按 `_healthBar` 位置定位。想调整尺寸/间距改文件顶部的 `BarWidth`、`BarHeight`、`GapAboveHpBar` 常量即可。

## 3.2 跨局传递：隐藏独立变量（原「枼绿素」遗物已移除）

- 原先的初始遗物**枼绿素已删除**，跨局传递改由 `HypeSystem` 里的隐藏独立变量 `_carryoverPolarity` 负责，不再占用遗物位、也不出现在遗物栏；
- **每场战斗结束**（`HypeCounterPower.AfterCombatEnd`）：记录「入脑 − 反踩」，正数=入脑、负数=反踩，钳制在 ±8；
- **每场战斗开始**（`HypeSystem.ApplyAsync` 末尾调用 `RestoreCarryover`）：按该值直接授予对应层数，于是第一回合就会触发入脑/反踩的回合开始效果；
- 落盘仍在 **`SaveScope.Profile`** 作用域（`polarity.json`），关掉游戏、换一局也仍在。

> 注意：按「每场战斗」结算而非只在整局开头结算一次。因为战斗能力不会跨战斗保留，若只在开局给一次，第二场战斗就断了传递。

**入脑端收益**：每回合稳定产出拉伸 + 3 点同接，是用来做「同接→反踩」转换的燃料。
**反踩端收益**：每回合稳定产出活力，挨打越多同接越多。

两端互相喂养：入脑产同接 → 卡牌转成反踩 → 反踩挨打产同接 → 再转回入脑。

## 4. 锡纸帽 / 独轮车：已暂时注释停用

两张衍生牌（`Cards/FoilHat.cs`、`Cards/Unicycle.cs`）的代码**整体注释保留**，不再注册进卡池，也不再由入脑/反踩发放：

- 入脑的收益改为「X 点拉伸 + 3 同接」；
- 反踩的收益改为「X 点活力」；
- 保留文件是为了后续可能恢复，随时取消注释即可。

## 9. 改卡面描述 / 加悬停提示

**文案在哪改**（改完必须重新打包 pck，描述才会进游戏）：

| 内容 | 文件 |
|---|---|
| 卡牌名与描述 | `assets/localization/{zhs,eng}/cards.json` → `VIRIDIS_CARD_<类名大写下划线>.title / .description / .smartDescription` |
| 关键词说明 | `assets/localization/{zhs,eng}/card_keywords.json` |
| 能力（buff）说明 | `assets/localization/{zhs,eng}/powers.json` |
| 遗物说明 | `assets/localization/{zhs,eng}/relics.json` |

**标黄与悬停是两件事**：

1. `[gold]词[/gold]` 只负责**变金色**，不会弹提示；
2. 真正的提示来自卡类里的 `AdditionalHoverTips`：

```csharp
protected override IEnumerable<IHoverTip> AdditionalHoverTips => new IHoverTip[]
{
    HoverTipFactory.FromCard<PaperTowel>(),          // 引用另一张牌 → 显示那张牌的完整卡面
    HoverTipFactory.FromKeyword(EarwormKeyword.Value), // 引用自定义概念 → 显示关键词说明
    HoverTipFactory.FromPower<WeakPower>(2),          // 引用原版 buff → 显示能力说明
};
```

本批 18 张新卡的描述里的引用词已全部标黄，并配了对应的 `AdditionalHoverTips`：提到别的牌用 `FromCard<T>()`，提到入脑/反踩/黑听/栽入/串子/同接/固无用 `FromKeyword(...)`，提到虚弱/覆甲/人工制品/活力/无实体用 `FromPower<T>(...)`。

## 8. 已知取舍 / 待验证

1. **反踩触发**用 `AfterDamageReceived`，多段攻击每段各 +1 同接，**没有每回合上限**；完全格挡的攻击同样计数（按 `DamageResult` 判断，非零即算）。
2. **锡纸帽 / 独轮车已停用**：相关文件整体注释，`GiveToken` 与栽培减费入口保留但不再使用；恢复时取消注释、并在入脑/反踩里重新调用 `TriggerEffect` 之外的发放逻辑。
3. **今日无绿 / 林黛绿**改的是抽牌堆第一张，不是随机一张。
4. 关键词 id 由 `Kaozi` 改为 `Earworm`，旧存档已挂的关键词会失效一次。
5. **双极滑条是自绘控件**，靠 Harmony 挂到 `NCreatureStateDisplay`，不同分辨率/缩放下的位置需要实机微调。
6. **跨局变量**写入 Profile 作用域；联机时各机各算，尚未做房主同步。
7. **原版关键词自动渲染**：`固有`（Innate）与 `消耗`（Exhaust）由引擎按 C# 关键词自动追加到卡面，JSON 里不要重复手写，否则会出现两遍；自定义「固无」`CardDescriptionPlacement = None` 不会自动渲染，必须写在 JSON 里。
8. 上述均需进游戏实测后再定数值。
