# 栽培（Cultivate）机制 Spec v0.1

> 状态：规则已定稿，数值待实测 ｜ 最后更新 2026-11-26
> 依据：本机游戏 v0.111.0 的 `sts2.dll` 实测数据（见文末「数据来源」）；运行时已适配 v0.113.1，卡池配额表尚未重新采样。

---

## 1. 一句话

栽培时，将指定的牌放入栽培区。你的回合开始时倒计时减少 1，降至 0 时收获。通常会生成 1 张稀有度高一级的牌加入手牌。

## 2. 术语

| 词 | 含义 |
|---|---|
| 栽培 | 动作，同时是模组关键词（RitsuLib 铸造 `CardKeyword`）。由**初始遗物 / 药水 / 卡牌描述**执行 |
| 栽培区 | 存放本场战斗中已栽培的牌。按钮显示张数，展开可看每张牌的倒计时或永久状态 |
| 栽培目标 | 本次效果指定的牌。通常从手牌选择，「吸芽」从抽牌堆选择 |
| X | 等待回合数 = 栽培目标**未升级时的原始费用**，钳制到 1~3 |
| 生长 N | 栽培区中的牌倒计时减少 N 回合，降至 0 时立即收获。卡牌可以指定只影响其中一部分 |
| 收获 | 按种下时的牌生成新牌加入手牌。手牌满时放入弃牌堆 |
| 永久栽培 | 具有此词条的牌被栽培后没有倒计时，按牌面触发效果。统计张数和使所有牌枯萎的效果都包括它 |

收获的牌使用其自身的关键词。世界树和腐殖循环额外生成的牌不会再次触发「每当你收获」。

## 3. 展示方式

牌面写明这张牌的动作、目标和数值。例如「种植」写「栽培 1 张手牌。抽 1 张牌。」选牌时，查看「栽培」说明可以知道要等几个回合；「收获」说明交代新牌的来源、去向与费用。「春化」的「生长」说明交代倒计时如何提前。

直接栽培的牌、按栽培区张数计算收益的牌，以及相关遗物与药水，均可通过游戏内悬浮说明查阅涉及的机制。战斗中的栽培区按钮也提供「栽培」「收获」说明。所有入口共用中英文 `card_keywords.json` 中的定义。

## 4. 结算流程

```
玩家执行栽培(target)
  → 从原战斗牌堆移出选中的卡牌实例
  → 在栽培区记录卡牌 id、升级状态、X 和剩余回合数
  → 你的回合开始时，剩余回合数 -1
  → 归零时，按收获规则生成对应的新卡牌实例，置入手牌
```

- 结算时点：**回合开始时**（玩家看到倒计时，拿到牌能立刻规划）。
- 战斗结束仍未收获 → 产物作废（本场战斗的临时物）。

### 4.1 永久栽培（特殊）

- 带“永久栽培”的牌是**被动**属性：只有被其它效果栽培时才生效，直接打出不会进入栽培区。
- 被栽培后不进入倒计时，`TurnsLeft` 视为无限，`Permanent = true`。
- 不参与收获，不产出卡牌；`生长`、`延缓`、`减半`、普通`立即收获`都跳过它。
- 「枯荣」「杀植物」会使栽培区中的所有牌枯萎，包括具有永久栽培的牌。
- 回合结束触发型（如小松绿）在己方回合结束时结算，数值存在 `Planting.StoredBlock/StoredDamage`，每次结算后翻倍。
- 小松绿打出时会把该卡牌实例的 `DynamicVars` 翻倍，因此之后被栽培时从翻倍后的数值开始；栽培区内的触发只改 `StoredBlock/StoredDamage`，不再改卡牌实例。
- 战斗结束随栽培区一起清空。

## 5. X 的确定

| 栽培目标 | X |
|---|---|
| 原始费用 0 | 1 |
| 原始费用 1 | 1 |
| 原始费用 2 | 2 |
| 原始费用 3 | 3 |
| 原始费用 ≥4 | 3（钳制） |
| `HasEnergyCostX`（X 费牌） | 1 |
| 状态 / 诅咒 / 任务（不可打出的牌） | 1 |

原始费用取 `card.EnergyCost.Canonical`，忽略升级带来的费用变化，也忽略战斗中的临时增减费。

## 6. 稀有度映射表

用户定义的阶梯（高→低）：

```
先古 > 稀有 > 罕见 > 普通 = 初始 = 事件 = 衍生 > 状态 = 任务 > 诅咒
```

对照引擎枚举 `MegaCrit.Sts2.Core.Entities.Cards.CardRarity`：

| 引擎枚举值 | 阶梯位置 | 收获目标的稀有度 |
|---|---|---|
| `Ancient` | 先古 | **同名卡 ×2**（特例，见 §8） |
| `Rare` | 稀有 | `Ancient` |
| `Uncommon` | 罕见 | `Rare` |
| `Common` / `Basic` / `Event` / `Token` | 普通 | `Uncommon` |
| `Status` / `Quest` | 状态 | `Common`（优先，见 §11 待定项） |
| `Curse` | 诅咒 | `Status`（按阶梯；见 §11 待定项） |

> **坑**：引擎枚举顺序是 `Basic→Common→Uncommon→Rare→Ancient→Event→Token→Status→Curse→Quest`，与本阶梯不一致，
> 因此**不能**直接用 `CardRarityExtensions.GetNextHighestRarityWithWrapping()`，必须自建映射表。

## 7. 收获池

**基础池**：小松绿角色卡池（`ModelDb.CardPool<ViridisCardPool>().AllCards`）。非先古收获只从这个池里选，不再并事件池、诅咒池、任务池或衍生池。

**诅咒特例**：栽培目标是诅咒（收获目标为 `Status`）时，改从全状态池选：

```csharp
ModelDb.CardPool<StatusCardPool>().AllCards
```

小松绿池里没有状态牌，不走这个特例会空池。

**先古特例**：栽培目标是先古牌时不做池检索，直接用被栽培牌的 `Id` 取回同名卡 ×2；跨角色先古牌也能取回，不再依赖当前角色池。

**过滤条件**：

1. `Rarity == 目标稀有度`
2. `CanBeGeneratedInCombat == true`（过滤后为空则放宽）
3. `CanonicalEnergyCost == X`（过滤后为空则回退同稀有度任意费用）

**空池回退**：

1. 忽略费用条件，取目标稀有度任意牌
2. 仍为空 → 不收获任何东西（不报错、不卡死）

## 8. 收获数量与属性

| 情况 | 数量 |
|---|---|
| 栽培目标为普通/罕见/稀有/状态/任务/诅咒 | **1 张** |
| 栽培目标为**先古** | **2 张相同的先古牌**（即被栽培的那张） |

- 允许两张同名。
- **保留升级**：栽培目标是升级过的，产物也是升级过的；产物本身不可升级则保持原样。
- **不保留附魔**：产物不带 `Enchantment`。
- **首次打出的费用**：若 X > 1，收获的固定费用牌首次打出至多消耗 1 点能量（`EnergyCost.SetUntilPlayed(1, reduceOnly: true)`）。
  X = 1 时不折扣。

## 9. 边界规则

| 情况 | 规则 |
|---|---|
| 手牌已满 | 产物进**弃牌堆** |
| 栽培目标为 X 费牌 | X = 1；收获池排除所有 `HasEnergyCostX` 的牌 |
| 栽培目标带附魔 | 附魔随目标一起消失，不影响 X |
| 同一张牌被栽培两次 | 目标已离开战斗，不可能；同名不同副本可以分别栽培 |
| 战斗结束/玩家死亡 | 未结算的栽培作废 |
| 产物是否触发"获得卡牌"类联动 | 待定（默认：不触发） |
| 栽培是否算"消耗/移除" | 不算，不触发消耗联动 |

### 9.1 吸芽的弃牌堆异常

- 2026-11-24 实战反馈：打出「吸芽」并选中抽牌堆的「防御」后，栽培区增加一张牌，弃牌堆也看见了「防御」。该场日志确认了一次栽培登记，以及此前曾打出另一张「防御」。日志未记录弃牌堆里的卡牌实例。
- 无界面引擎回归：当抽牌堆和弃牌堆各有一张同名「防御」时，选中的实例离开战斗并登记一次栽培，弃牌堆的同名实例仍在原处。已打出的「吸芽」按技能牌规则进入弃牌堆。
- 已修正的边界情况：若目标在选牌后移到了其他牌堆，普通和永久栽培都会拒绝登记。成功登记前会确认选中的实例已离开战斗。

## 10. 实现映射（待验证）

| 需求 | 引擎 API |
|---|---|
| 首次打出至多 1 费 | `EnergyCost.SetUntilPlayed(1, reduceOnly: true)` |
| 读原始费用 | `CardModel.EnergyCost.Canonical` |
| 读稀有度 | `CardModel.Rarity` |
| 枚举角色池 | `CardPoolModel.AllCards` / `GetUnlockedCards(...)` |
| 枚举事件池 | `ModelDb.CardPool<EventCardPool>()` |
| 生成卡牌实例 | `ModelDb.Card<T>()`（或 `CardModel` 克隆） |
| 置入手牌 | 待查（`CardPile` / `CardCmd` 相关） |
| 回合开始钩子 | 待查（`CombatStateHooks` 或 Power 的 turn-start） |

状态保存建议：用一个挂在玩家身上的战斗内 Power 存列表（卡 id + 升级等级 + 剩余回合），
Power 自带回合开始回调，且战斗结束自动销毁，比静态字典安全。

## 11. 待定项

1. **诅咒的收获目标**：已定：产出 `Status`，从全状态池随机（见 §7）。
2. **状态/任务的收获目标**：目前只用 `Common`，不接受 `Basic`/`Event`/`Token`。
3. **栽培目标范围**：由触发效果指定。多数从手牌选，「吸芽」从抽牌堆选。
4. **先古 ×2 的确认**：已定：2 张被栽培的那张牌；跨角色用全局 `Id` 查回同名。
5. **产物是否触发"获得卡牌"联动**。
6. **先古档是否限流**：小松绿池已有 11 张先古，产出随机性较大。

- `sts2.dll` 元数据（Mono.Cecil 读取构造函数常量）：596 张卡的稀有度 / 费用 / 所属池

## 13. 枯萎与直播体系

- **枯萎**：移除一张栽培区中的牌，本场战斗失去这张牌，不触发收获。可移除有倒计时和永久栽培的牌。实现为 `CultivateSystem.Wither(player, Planting?)`，未指定目标时随机。
- **同接**：战斗内计数，回合内每打出一张牌 +1，回合结束时清零；挂在隐藏的 `HypeCounterPower` 上，能量球右侧用 `HypeCounterUI` 显示。小松绿始终显示；其它角色只在任意战斗牌堆里出现 `IHypeCard` 或带 `ViewerCount` 关键词的牌时显示。计数器本身对所有玩家挂载，保证中途加入同接牌也能开始累计。
- **考子**：回合开始时按层数增加同接（`KaoziPower`）。
- **反踩**：每回合前 X 次打出的牌不加同接（`AntiStompPower`，由 `HypeCounterPower` 在结算前调用 `TryBlockCard`）。
- **串子**：回合开始时进行 X 次随机判定，每次给 1 点活力或 1 点拉伸（`ChuanziPower`）。
